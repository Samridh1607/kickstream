Architecture and data flow

One process carries the match and the stream

Kickstream runs as one program. Locally that is a FastAPI process on port 8000 plus the Vite app on port 5173. On Azure, deploy/terraform puts both behind a single Container App. Matches, the studio, and live streams are held in that process’s memory, so the app is pinned to one replica.

Pipeline

A match moves through five stages. The seven match agents sit beside that line and publish findings onto the same stream the browser reads.

  1. IngestSimulator, detector file, or a match source
  2. InterpretAnalytics: stats, pressure, events
  3. ExplainNarration in Fan and Analyst wording
  4. RenderOverlay graphics and scene widgets
  5. PersonalizeGateway filters by mode, language, favourite

The gateway fans the match out with Server-Sent Events and WebSockets. A page that joins late is not given the whole history of pitch scenes: it is replayed the newest pitch scene and the newest player report. WebSockets are accepted only from pages on the host the pipeline was reached at. Behind a proxy that rewrites Host, public names go in KICKSTREAM_ALLOWED_HOSTS. On the Container App, KICKSTREAM_PUBLIC_HOSTS is the app’s own FQDN, and requests through it reach only what the public-host gate allows.

Narration and agents

Narration is a second writer path from the match agents. Four Microsoft Agent Framework agents write when a model is configured: a Commentator and a Tactical Analyst on each key moment, a Recap Writer at half-time and full-time, and a Localizer into Spanish and Hindi. Each item is written once per mode and language and sent to every viewer on that variant, so model cost does not grow with the audience. Output is cached. If the model is slow, rate-limited, or unusable, that item falls back to a template and is marked scripted.

The seven match agents compute structured findings. Only the Explainability Agent produces prose, in English, at most 20 explanations a match, from templates when no model is set. Switching an agent off is stored in .data/agents.json. Agents that listen to it then have less to work on.

Going live does not send a separate video file per platform. The studio’s clean output (/studio?output, 1920×1080) is opened in a hidden Chromium browser. ffmpeg encodes that picture once and copies the stream to every destination. Microsoft Edge is used when it is present. Auto live captures /live?output the same way.
