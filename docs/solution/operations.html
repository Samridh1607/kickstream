Deployment and operations

Deploy, probe, and tear down

deploy/deploy.ps1 and deploy/deploy.sh sign in with the Azure CLI, set ARM_SUBSCRIPTION_ID from az account show, create the registry first, build the image, then apply the rest of the stack. deploy/destroy.ps1 and deploy/destroy.sh remove that stack, including the Entra app registration. The PowerShell destroy script shows the plan and asks unless -Force is passed.

Toolchain

  • Terraform 1.9 or newer. Providers: azurerm ~> 4.0, azuread ~> 3.0, azapi ~> 2.0, random ~> 3.6.
  • Azure CLI, already logged in. The subscription comes from the account that is current.
  • Image build: az acr build by default, or Docker on the operator’s machine with -LocalBuild / --local-build.
  • Default region centralindia. Communication Services data location defaults to India. The app name defaults to kickstream and must match ^[a-z][a-z0-9-]{1,22}[a-z0-9]$.

The script applies Terraform twice. The first apply targets azurerm_container_registry.main so the image has a registry. The image is kickstream:<tag>, and the tag defaults to a timestamp. The second apply passes image_tag. The Container App cannot start until that image exists.

Size, probes, and runtime switches

The container asks for 2 vCPU and 4 GiB. The hidden browser and ffmpeg need at least 2 vCPU to go live, and Container Apps pairs 2 GiB of memory with each vCPU. Ingress is external, transport auto, 100 percent of traffic on the latest revision.

Both probes call /api/health on port 8000, straight to the container, past the sign-in. The startup probe runs every 10 seconds with a 5-second timeout and allows 30 failures. The liveness probe waits 30 seconds, then every 30 seconds, with a 10-second timeout and 6 failures. A process that stops answering is restarted. Auto live then reads its screens and its 24/7 stream back from /data. The health payload reports the match, the stream’s state, and whether auto live is on.

Defaults an operator can override in terraform.tfvars (git-ignored; the example file lists every key): autolive true, public_view true, real_sources false, speech_sku S0, speech_daily_chars 200000, match_log_ttl_days 90. Optional values that become environment variables only when set: API-Football key, LLM base URL, model, and key, Foundry project endpoint and deployment name.

What an operator watches

  • Container App logs in the Log Analytics workspace, kept 30 days.
  • /api/health for match, stream, and auto live.
  • The studio top bar and the Stream tool for each destination: connecting, live, retrying, failed.
  • Disk on the file share. A Record to file destination left on under Stream 24/7 fills the share. Stream 24/7 is for platforms.
  • Speech characters. Past speech_daily_chars, auto live falls back to the browser voice until midnight UTC, and a captured stream that needed Azure speech goes quiet.

Outputs after apply: the studio URL, the auto-live URL, the registry name, the resource group, the Cosmos endpoint, and the Container App name.
